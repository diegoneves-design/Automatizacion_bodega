# Ensayo interno de la pauta

Antes de recibir a nadie se ensaya la pauta completa dentro del equipo. Una tarea ambigua se descubre aquí, cuando corregirla todavía no cuesta nada (así lo pide el Avance 6).

**Quién participa.** Una persona que hace de participante y que **no diseñó las tareas**, y quien facilitará de verdad. Si hay una tercera, registra. Se ensaya con el prototipo publicado, no con una copia.

**Cuándo.** Al menos una vez completa y, si algo cambia en la pauta o en el prototipo, otra vez.

## Antes de empezar

- [ ] El prototipo muestra la primera pantalla y se presionó **Reiniciar demo** (las órdenes 3001 y 3002 sin cambios).
- [ ] Hay un reloj o cronómetro a la vista de quien facilita.
- [ ] Se imprimió la pauta (`docs/pauta-validacion.pdf`, 2 planas) y se tiene la planilla (`planilla_registro.csv`) con el código del ensayo (por ejemplo, E01).
- [ ] La grabación de pantalla y voz está probada en el dispositivo que se va a usar: se oye la voz y **no aparece la cara**.

## Durante: leer la pauta completa en voz alta, en orden

Quien facilita lee cada etapa tal cual y cronometra. Anota la hora real de cada una.

| 1. Bienvenida y consentimiento | 2 min | | |

| 5. Cuestionario SUS | 3 min | | |
| 6. Preguntas de cierre | 2 min | | |
| **Total** | **19 min** (1 minuto de holgura) | | |

Reglas del ensayo, las mismas que en la sesión real:
- [ ] El escenario de cada tarea se lee **una sola vez, tal cual**. Si piden repetirlo, se repite.
- [ ] **Nadie ayuda.** Si quien facilita se escapa y señala un botón o dice «va bien», se anota como ayuda.
- [ ] Quien hace de participante **piensa en voz alta**; si se queda callado, se le pregunta «¿Qué está pensando ahora?».
- [ ] Si lleva más de 2 minutos trabado, se usa la frase de la pauta y, si sigue sin avanzar, se anota «no completa».

## Qué se comprueba antes de dar el ensayo por bueno

- [ ] **Duración:** la suma real no pasa de **20 minutos** y deja al menos 1 minuto de holgura. Si no, se recorta (la segunda pregunta de contexto o la segunda de cierre, nunca el tiempo de las tareas) y se vuelve a ensayar.
- [ ] **Ninguna tarea nombra un botón ni una pantalla** en el escenario. Se lee cada escenario buscando «Cargar», «Validar», «Preparar guía», «Registrar cambio».
- [ ] **El criterio de éxito de cada tarea lo puede verificar otra persona mirando la grabación**, sin preguntarle a quien facilitó. Se prueba: alguien que no estuvo mira el video y dice si la tarea se completó y en qué minuto.
- [ ] **Ninguna pregunta sugiere la respuesta** ni pide opinión sobre el futuro. Se anota cualquiera que lo haga (ver `revision-avance6.md`). Se presta atención a las dos preguntas que se reescribieron: la 2 de contexto («antes de dejar lista la guía, ¿qué revisó?») y la 2 de cierre («¿en qué se parece o en qué no se parece?»). La frase 1 del SUS se queda.
- [ ] **La tarea 2 se puede verificar de oído.** Quien mira la grabación debe poder decir, solo con lo que se oye, si la persona dijo en voz alta cuál es el código marcado «no existe».
- [ ] **Los tramos de la tarea 2** (terminar sin ayuda: 3 o más se cumple, 2 entorpece, 1 o menos bloquea) se confirman o se corrigen aquí, y la regla de fallas del sistema también.
- [ ] **Reiniciar demo funciona** y deja las dos órdenes como al principio entre una vuelta y otra.
- [ ] **Los tiempos de cada tarea** salen de la grabación con el reloj del video, sin depender de que alguien lo haya cronometrado de memoria.
- [ ] **Ningún dato personal** quedó anotado (ni en la planilla ni en el nombre de los archivos de la grabación).
- [ ] La planilla del ensayo se **descarta** o se guarda con el código E01; no se mezcla con la de los participantes reales.
